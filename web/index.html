What can I trust without a damage formula?

Troop stock limits, march capacities and timing. A rally only scores if it hits before the event ends. A 25:01 start is too late with a five-minute countdown.

What still needs alliance testing?

Damage totals, best troop ratios and how the game credits individual damage. Try both count-combination modes; a ranking that changes needs battle-report evidence.

Equal-tier community Attack weights are roughly infantry 1, cavalry 3, archers 4; the reported archer bonus against Bear raises its default weight to 4.4. Leader buffs and troop-count scaling change the final result.

Read the full damage equations and limitations

There is no official published Kingshot damage formula in the sources we found. The model uses community researchers' equations and troop tables. We do not treat agreement between fan tools as independent proof.

Equal-tier base Attack is about Infantry 1, Cavalry 3, Archers 4. The reported 10% archer counter bonus makes the archer coefficient about 4.4. A coefficient is not a fixed damage-per-soldier ratio: troop count scaling, tier, the host's Attack and Lethality, and hero effects all matter.

Community square-root model: each type's contribution is proportional to √(type count × min(total count, 5,000)) × base Attack × (1 + host Attack / 100) × (1 + host Lethality / 100) × type bonuses. Common battle constants and ten rounds are absorbed into one score scale. The linear size slider does not apply in this mode.

Where counts are combined: per-player mode calculates each player's troop types separately. Pooled mode combines each type across the whole rally, uses a weighted mean coefficient for mixed tiers, and allocates that type's damage back by weighted troop counts. The game's exact personal-credit method is unresolved here. Try both scopes before relying on a ranking.

Troop weights, linear count: troops × type coefficient. This is a simpler sensitivity alternative. Old equal-type model: treats all types equally and preserves the earlier calculator. New troop-aware results are not comparable with old calibrated coefficients unless refitted.

Host strength is a residual multiplier for fixed heroes and other effects. If you enter report Attack and Lethality separately, refit Host strength; an old coefficient may already contain those bonuses. Historical event score and account power never directly multiply damage.

At equal tier and equal type bonuses, the unconstrained square-root optimum is proportional to the square of each type's coefficient. With 1 / 3 / 4.4 that is about 3.4% / 30.7% / 65.9%, not a universal 10 / 10 / 80. Stronger archer bonuses can push archers higher. This is a model result, not an official formation recommendation.

“Choose mix from damage model” optimizes the next available march under stock limits. It does not jointly optimize every future rally. It assumes no required minimum percentage for activating a hero skill. Use the target-ratio policies if your fixed hero setup needs a particular mix. Troop tier, extra-attack rates, mixed-tier aggregation, procs and personal-score credit remain modelling limits.

The demo inventory uses user-chosen stock percentages and linearly interpolates total troop counts across the chosen power range. Buildings, heroes and research also contribute to power. Power-based estimates are placeholders until replaced with counts.

Timing and troop limits

Troops and each troop type are reserved when sent and are unavailable until returning. A player may join a rally once, may use their configured joining slots, and may lead one separate rally. Rally capacity includes the leader. 14 joiners is an editable starting assumption.

Only impacts before the event ends count. With a 300-second countdown, a rally started at 25:01 cannot score. Travel makes the final safe start earlier still. For an assigned Bear trap group, joining travel uses city-to-city coordinate estimates; rally travel uses the chosen trap position. Calibrate these estimates against measured marches. Other rosters use per-player travel inputs. Heroes, losses and unpredictable reaction delays are not individually simulated.

Normalizing the baseline scales it once to the target (2B by default) and uses that same scale for all scenarios. It does not validate the model. Turn it off after report calibration. The search compares a bounded set of setups; it does not prove the best possible alliance strategy.
